# Documento de requisitos

O projeto Catálogo da Biblioteca do Curso tem como objetivo facilitar o acesso dos estudantes às informações do acervo bibliográfico relacionado ao curso de Análise e Desenvolvimento de Sistemas. A solução consiste em uma página web que apresenta livros em cartões com título, autor, área de conhecimento, ano de publicação, descrição e situação de disponibilidade. A interface permite consultar o acervo, filtrar os livros por categoria e identificar quais obras possuem exemplares livres, contribuindo para uma localização mais prática dos materiais de estudo.
Entre as principais dificuldades que o projeto busca solucionar estão a dificuldade de verificar a existência e a disponibilidade de uma obra antes de se deslocar até a biblioteca, a localização de livros por título ou autor, a identificação de materiais relacionados a áreas específicas e a repetição de perguntas sobre o acervo. Na entrevista fictícia elaborada para a atividade, foi considerada, exclusivamente como estimativa acadêmica, a ocorrência de aproximadamente dez perguntas por dia sobre títulos, autores e disponibilidade. Esse número não corresponde a uma medição real.
O sistema precisa apresentar os livros cadastrados por meio de cartões gerados dinamicamente a partir do array LIVROS, definido em dados.js. Cada cartão deve exibir o título, o autor, a área de conhecimento, o ano, a descrição e um indicador de disponibilidade. A página deve permitir pesquisar livros por título ou autor, sem diferenciar letras maiúsculas de minúsculas, e filtrar os resultados por área de conhecimento. Também deve permitir combinar a pesquisa textual com os filtros, exibir somente os livros disponíveis e retornar à listagem completa quando os critérios forem removidos.
O sistema deve atualizar o contador de livros encontrados após cada pesquisa ou filtragem e apresentar uma mensagem informativa quando nenhum livro corresponder aos critérios selecionados. Ao selecionar um livro, deve ser possível consultar suas informações completas e retornar à listagem. A interface deve apresentar o selo “Disponível” quando houver mais de um exemplar livre, “Último exemplar” quando houver exatamente um exemplar livre e “Emprestado” quando não houver exemplares livres. Deve existir uma opção para limpar os critérios de pesquisa e restaurar a listagem inicial.
A implementação deve utilizar HTML5, CSS3 e JavaScript puro, sem frameworks, bibliotecas externas, back-end, banco de dados ou armazenamento persistente. Os arquivos index.html, style.css, dados.js e script.js devem manter suas responsabilidades separadas, com os dados armazenados em dados.js e a lógica de apresentação e filtragem em script.js. O array deve conter pelo menos oito objetos, cada um com cinco ou mais propriedades, incluindo pelo menos uma propriedade numérica e uma booleana. A página deve abrir diretamente pelo arquivo index.html, funcionar nos navegadores modernos e manter sua legibilidade em telas de 400 pixels de largura, sem rolagem horizontal desnecessária. A interface deve utilizar elementos HTML semânticos, campos com rótulos associados, identidade visual coerente, cabeçalho com o nome do projeto e rodapé com os nomes de todos os integrantes.
O escopo contempla a consulta aos livros, a filtragem de informações e a apresentação da disponibilidade conforme os dados cadastrados. Não estão incluídos cadastro e autenticação de usuários, empréstimos, devoluções, reservas, multas, gerenciamento administrativo do acervo ou integração com sistemas externos. Como o projeto utiliza dados estáticos, a disponibilidade apresentada não será atualizada automaticamente por movimentações reais da biblioteca. Para atender integralmente ao briefing, a versão atual ainda precisa incorporar a pesquisa por autor, a atualização da pesquisa enquanto o usuário digita e a visualização detalhada do livro selecionado, pois essas funcionalidades não estão implementadas nos arquivos JavaScript enviados.
